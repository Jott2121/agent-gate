## What this repo is

`agent-gate` (PyPI: `mcp-agent-gate`) is an MCP server an agent calls on its own work before it claims done: a fail-closed checklist, then an append-only sha256 receipt ledger. The core is stdlib; `agent_gate/server.py` is the thin MCP adapter. The bar this repo holds itself to is the CI coverage gate: pytest fails if line coverage of `agent_gate` drops below **90%**. Reproduce with the test command below. README also says the tree is "currently 97% covered"; that sentence is a published number — see Known traps before treating it as a live measurement.

- **Status:** active · **License:** MIT · **Package:** `mcp-agent-gate`
- **Entry points:** console script `agent-gate` = `agent_gate.server:main` (verified in pyproject.toml). Also `python -m agent_gate.server`.
- **Part of:** the governed-agent stack (rag-guard · graph-guard · agent-gate · crucible · oracle-gate · agent-cost-attribution · bow · fleet-mode)

## Non-negotiables

1. **No employer data. Ever.** This is personal work on personal equipment. Never add, paste, paraphrase, or "anonymize" anything from an employer's systems, documents, tickets, chats, or datasets: no workforce data, internal URLs, or confidential or export-restricted material. No employer names in any file, no internal acronyms, no realistic HR records. Synthetic data only, generated by a committed script with a fixed seed. If a prompt looks like it came from work, stop and ask. `scripts/scan_blocked_terms.py` enforces this in CI with no exempt files.
2. **Receipts over hype.** Every number in README, docs, PR descriptions, or posts must be reproducible from a committed command. Link the command and the artifact (CI log or `scripts/check_receipts.py`). No "blazing fast", "SOTA", or "production-grade" without a measurement.
3. **Honest benchmarks.** Report nulls and regressions at the same prominence as wins. State n, seeds, model + version, date, and cost when a comparison exists. This repo does not run model comparisons. Never delete an inconvenient run; mark it superseded with a reason.
4. **Fail closed.** Gates, validators, and guards deny on error, timeout, missing input, or unparseable output. `Gate.evaluate` passes a check only on literal `True`. Never weaken a guard to make a test pass. Never catch-and-ignore exceptions in a decision path.
5. **Tests and CI are the definition of done.** New behavior ships with a test that fails without it. Bug fixes ship with a regression test. Do not lower `--cov-fail-under=90`. Do not mark tests `skip`/`xfail` to get green. `tests/test_server.py` skips only when the `mcp` SDK is missing; CI installs it.
6. **Model never grades its own output.** Prefer mechanical verdicts (tests, schema checks, `verify_chain()`). Where a judge model is needed, use a different model lineage from the author and record both.
7. **Irreversible = human-gated.** No force-push, no history rewrite, no publishing to PyPI, no tagging releases, no posting anywhere. Open a PR; a human merges.

## Code style

- Python 3.11+. `gate.py` and `ledger.py` stay stdlib-only. A new runtime dependency needs a one-line justification in the PR.
- Type hints on public functions. Small pure functions. No global mutable state.
- Errors: raise specific exceptions; log with context; no bare `except`.
- Secrets only via env vars; never print secret values. Ledger path override is `AGENT_GATE_LEDGER` (default `~/.agent-gate/receipts.jsonl`).
- Don't commit build output: `__pycache__/`, `*.pyc`, `.coverage`, `.venv/`, `receipts.jsonl`.

## Known traps

- **The shell guard blocks `git pull --rebase`.** The hook matcher includes `git pull` and `rebase`, so a rebasing pull reaches `.cursor/hooks/guard-shell.sh` and is denied. A plain `git pull` is allowed. The script denies any command containing `rebase`, and it denies `git reset` when `--hard` appears anywhere, including `git reset HEAD --hard`. Force-push is denied when `--force`, `--force-with-lease`, or a standalone `-f` appears anywhere on a `git push`, including `git push origin --force` and `git push origin -f`. `curl` or `wget` piped to `sh` or `bash` is denied. A normal `git push`, `curl`, or `wget` asks first. A payload whose `command` is missing, blank, or not a string is denied. Invalid JSON exits non-zero. Pull with merge, or leave updating the branch to a human. Do not weaken the hook.
- **Coverage floor is 90, not the README percentage.** `ci.yml` uses `--cov-fail-under=90`. README says "currently 97% covered". `scripts/check_receipts.py` prints the measured figure and does not edit README. Do not "correct" that sentence in an unrelated PR, and do not lower the floor so a run stays green.
- **`16.7%` is sabot's number**, cited in the companion paragraph. This repo cannot recompute it.
- **Demo hashes are not receipts.** `Ledger.append` hashes the timestamp. `examples/demo.py` uses the wall clock and sleeps. The truncated hashes in the README will not match a fresh run.
- **Server tests and coverage.** Skipping `tests/test_server.py` while `mcp` is installed drops `server.py` out of the coverage number and hides a broken entry point. The 1.x import fallback (`except ImportError`) is only covered when that older SDK is what imports.
- **Blocked terms are stored as hashes only.** Never write a blocked term in plain text, even in policy files, tests, or commit messages; the scan covers every tracked file. Add a term by appending its digest to `.github/blocked-terms.sha256` (the file header shows the command) or through the `BLOCKED_TERMS` repo secret. Tests plant synthetic terms in temp dirs.
- **Do not commit a ledger.** `receipts.jsonl` and `.agent-gate/` are gitignored. Tests point `AGENT_GATE_LEDGER` at a temp file.
